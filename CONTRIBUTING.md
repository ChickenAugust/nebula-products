# Contributing to Nebula

## Before changing code or hardware documentation

Read:
- NEBULA_SPEC.md
- ARCHITECTURE.md
- the relevant branch README
- relevant decisions and requirements

## Change discipline

- Keep changes focused.
- Preserve existing decisions unless intentionally superseded.
- Document new assumptions.
- Never invent measurements or test results.
- Use exact part numbers for hardware decisions.
- Tie validation results to hardware and software revisions.

## Commit messages

Use an imperative summary such as:
- Add USB-C power-path architecture
- Document display interface
- Add battery telemetry service
